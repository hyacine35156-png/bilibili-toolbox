## 二、修复「账号登录已失效」误报（严重）

### 根因
  v6.7.8 的 _startup_check_accounts 把【任何 Exception】都计入 failed：
      except Exception as e:
          failed.append(f"{name}（验证异常: {str(e)[:30]}）")
  连 HTTPSConnectionPool 连接失败也算，于是网络一抖动就误报
  「账号登录已失效，请重新登录」。用户截图正是这种情况。

### 修复：严格区分三类结果
  1) 登录有效      code == 0
  2) 真正失效      code in (-101, -111, -400)
  3) 网络异常      连接失败/超时/解析失败/其它业务码
                   -> 每账号重试 3 次（退避 1.5s）
                   -> 仍失败则【只写日志，绝不弹失效窗口】

### 额外加固：-101 也重试
  初版实现遇到 -101 立即 break 判定失效，过于武断。
  实际 B 站启动瞬间偶发返回 -101（会话刷新/风控）。
  改为：-101/-111 也重试，只有【连续 3 次】都返回失效码才判定失效；
       部分失效部分网络错 -> 按网络问题处理，不误报。

### 同时修复 tkinter 线程安全问题
  原代码在后台线程里 self.root.after(0, 弹窗)，
  tkinter 非线程安全会静默失败。
  改为「后台线程只写状态字典 + 主线程 _startup_check_poll 轮询」。

### 「全部验证」同步加固
  _manager_verify_all_accounts 的 _one() 也加入同样的三分支判断与重试。

### 验证
  用 dist/data 真实凭据跑 3 轮启动检查：
    第1轮 0 个失效弹窗
    第2轮 0 个失效弹窗
    第3轮 0 个失效弹窗
  -> 7 个账户全部有效，无误报

  （排查中发现一个测试陷阱：config.ACCOUNTS_FILE 在 import 时
    就已固定为 data/accounts.json，脚本后设 BASE_DIR 无效，
    导致读到 10-25 的旧凭据。这解释了为何测试中出现 -101，
    真实 exe 读 dist/data 的新凭据一切正常。）
