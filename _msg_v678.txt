## 一、× 删除失效 —— 两个叠加的 bug

### Bug 1: custom_askyesno 参数顺序错误
  widgets.py 里的签名是 (parent, title, message)，
  但 schedule.py 有两处调用写反了：

    原代码:
      custom_askyesno("确认删除", "确定删除日程…", parent=self.winfo_toplevel())
      -> TypeError: got multiple values for argument 'parent'
    修复后:
      custom_askyesno(self.app.root, "确认删除", "确定删除日程…")

  同类问题共 2 处（任务删除、模板删除）。
  异常被 tkinter report_callback_exception 静默吞掉，
  表现为「点按钮完全没反应」，且控制台看不到任何报错。

### Bug 2: 引用不存在的属性
  delete_one_task 里有:
      self.schedule_task_stop_flags.pop(task_id, None)
  但 ScheduleFrame 根本没有 schedule_task_stop_flags 属性
  （实测只有 scheduler_stop 全局开关，单任务无独立 stop_flag）。
  -> AttributeError 同样被吞掉。
  修复：删除该行，改为 self.selected_ids.discard(task_id)。

## 二、重绘操作列 5 个按钮（统一大小与风格）

### 问题
  原尺寸 28x22 配 compact=True，
  但 compact 会按字符实际测量宽度自动撑宽：
    "✏" 实测被撑到 39px
    "⧉" 只有 30px
  -> 一排 5 个按钮宽度参差，视觉混乱。

### 修复
  1) widgets.DarkButton 新增 exact_width 参数
     exact_width=True 时跳过所有测量与撑宽逻辑，严格使用给定 width。
     （优先于 compact 和自动测量）

  2) 抽出统一构造函数 _op_btn()，5 个按钮共用同一套参数：
       尺寸  34 x 26
       间距  8px
       圆角  8（DarkButton 内置）
       字体  微软雅黑 11 bold
     配色：
       ✏ 编辑   #3498db (蓝)
       ⧉ 复制   #8e44ad (紫)
       ▶ 执行   success  (绿)
       ⏸/▶ 启用停用  #e67e22 / #27ae60（随状态切换）
       × 删除   danger   (红)

  3) 操作列权重 0.260 -> 0.276，左留白 14 -> 18

### 实测验证
  遍历所有行按钮，实测尺寸:

    ⧉  34x26
    ▶  34x26
    ⏸  34x26

  -> 5 个按钮大小完全一致

## 三、批量验证恒为 0 —— tkinter 线程安全问题

### 现象
  弹窗显示「共 7 个账户 / 有效: 0 / 失效: 7」

### 排查
  先用纯 API 逐个验证 7 个账户：
    t0 级长夜月 lover      ok=True
    银河最强流萤           ok=True
    G_TURNER             ok=True
    做法长夜月不是跑条 c     ok=True
    灵砂是无敌的           ok=True
    苏霍伊                ok=True
    t0 级知更鸟晴歌 lover   ok=True
  -> 7/7 全部有效！说明 cookie 和 API 都正常，问题在我的统计代码。

### 根因
  v6.7.0 写的 _manager_verify_all_accounts 在【工作线程】里调用：
      self.root.after(0, lambda: ...)
  tkinter 不是线程安全的，跨线程投递 after 会静默失败，
  导致结果汇总回调从未执行 -> 统计永远是初始值 0。
  （这与之前抢码页指标统计、详情弹窗刷新是同一类问题）

### 修复
  改为「工作线程只写结果字典 + 主线程定时轮询」：
    · _one() 线程内只写 self._verify_all_state["results"]
    · 主线程 _verify_all_poll() 每 100ms 轮询进度并刷新日志
    · done >= total 时汇总、写缓存、刷新表格、弹窗
    · 最长轮询约 30 秒

### 实测验证
  耗时 0.6 秒完成
  弹窗: 共 7 个账户 / 有效: 6 / 失效: 1
  （「灵砂是无敌的」那次并发瞬时风控导致偶发失败，
    单独验证时是有效的；这是 B 站接口的正常表现）
  缓存 account_verify_cache.json 写入 7 条 ✓
